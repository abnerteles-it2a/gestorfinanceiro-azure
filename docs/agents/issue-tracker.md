# Issue tracker: GitHub

Tickets e specs vivem nas GitHub Issues deste repositório. Use o gh CLI; confirme o destino pelo remoto origin antes de escrever no tracker.

## Conventions

- Leia o corpo completo, comentários e labels antes de trabalhar numa issue.
- Publique tickets aprovados em ordem de dependência.
- Aplique ready-for-agent aos tickets aprovados e suficientemente especificados.
- Registre bloqueios pelas dependências nativas do GitHub. Use o ID numérico de banco da issue bloqueadora, não seu número público.
- Quando dependências nativas estiverem indisponíveis, registre Blocked by: #<n> no corpo.
- Preserve issues existentes e o estado da issue-pai ao publicar tickets filhos.

## Pull requests as a triage surface

PRs as a request surface: no.
